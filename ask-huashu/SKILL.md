# Ask Huashu

你不用记住每个 skill。带着想做的东西，或觉得不对劲的作品来问。

**先想这件作品要让人看懂什么、感受到什么，再决定它长什么样。** 读真实内容，拆真实参考，把方向做成看得见的初稿，再根据作品修改。这里整理的是花叔公开实践里的创作取舍；以作品和当下用户的意图为准。

## 先找卡点

读已有素材、当前版本和用户反馈。辨清这次卡在**内容、表达、制作还是修改**。只问会改变路线的问题；已有答案直接沿用。

- **还没想清讲什么**：先把受众、核心判断和支撑材料说清。选题与资料走[内容与研究](references/content.md)。
- **内容有了，做出来没感觉**：先判断概念、构图、材料或节奏哪里失效，读[创作判断](references/creative-judgment.md)，再选视觉路线。
- **方向已经确定**：从现有设计、脚本、代码和品牌资产继续，进入对应的制作或修改步骤。
- **只是在问该用哪个**：给出首选、适用原因和下一步；涉及美术时，推荐深入到成员里的具体风格或视觉语言。用户已有交付请求时，选定路线后继续完成工作。

完成这一步时，能说清：**给谁看，让他看懂或感受到什么，眼下要解决哪一个问题。**

## 主线：内容 → 表达 → 作品 → 反馈

### 1. 找到作品的主张

看实际产品、原文、数据、截图和用户给的参考，找出最值得被看见的一件事。区分事实、用户偏好和创作设想。缺事实就查，缺个人经历就向本人取材；素材的身份跟着来源走。

研究与写作走[内容与研究](references/content.md)，数据和正式报告走[数据与文档](references/data.md)。已有可靠内容可以直接进入下一步。

完成条件：主张有材料支撑，待核实的内容已经标明，作品承诺的事情与素材相符。

### 2. 让内容决定形式

先想观众在哪里看、看多久、需要怎样理解，再选媒介。演讲页靠现场讲述，信息图要独立读懂，界面要能操作，动画用变化让关系显现。

| 要做的东西 | 主路线 |
|---|---|
| 视觉方向、HTML 原型、信息图、设计评审 | `huashu-design` 完整版 |
| 发布片、产品更新片、需要指着画面修改的动效 | `huashu-motion` |
| 艺术风格动画、参考动画拆解、机制或口播解说 | `huashu-art-motion` |
| Seedance 提示词或白模参考视频 | `seedance-skill` |
| 图片、封面、幻灯片 | 按用途和当前宿主选[视觉制作](references/visual.md)里的入口 |

动画的边界、两个同名 design、宿主专用技能也在[视觉制作](references/visual.md)。选择一个主流程，辅助技能只补眼前缺口。

**用户不知道该选什么风格时，由这里承担判断。** 读[风格顾问](references/style-advice.md)，进入所选成员的实际风格库、样张和方法卡，把场景转成具体建议。说明推荐哪一款、它如何服务这份内容、另一个方向的取舍，以及实现需要什么。已有品牌或参考也要解释怎样用于眼前任务。

只问建议时，把画面说到用户能想象和选择；要求制作时，再按成员流程做真实初稿。已确定的方向继续深化。

完成条件：建议已经落到**技能＋具体风格/视觉语言＋适配理由＋画面做法**；风格来源、样张是否看过和实现限制有据可查。用户无需懂术语也能理解取舍。

### 3. 先做最难成立的那一处

挑出决定成败的一页、一帧或一个镜头，按交付尺寸做出来。它可能是产品第一次被看懂的瞬间、最密集的信息页，或整片最难的视觉转换。先验证它，再把同一套表达扩展到整件作品。

参考作品提供的是办法：字与图怎么组织，笔触和光怎样塑造空间，镜头为什么在此时动。新题材重新构图。需要推敲这些判断时读[创作判断](references/creative-judgment.md)，制作细节留给成员流程。

完成条件：代表片段已经实际渲染或制作，核心意思、阅读尺度和实现路径站得住。

### 4. 对着作品改

静帧看构图、层级和细节，正常速度看节奏、连贯性与声音。把“太素”“不顺”“没重点”定位到具体页面、元素或时刻，再作对应修改；检查修改对前后内容的影响。

交付实际产物，说明看过什么、验证过什么、仍有什么限制。一次作品的选择留在这次作品里；用户明确要求记住的偏好才进入其个人记录。可复用的方法来自反复出现的证据。

完成条件：请求的产物可用，主要表达问题已经解决，技术通过与人的审美判断分别说清。

## 其他入口

主线只服务创作；其它工作直接进入合适的分支。

- **已有文章要改、去 AI 味或转成别的渠道** → [内容与研究](references/content.md)。保留原意、事实和作者的真实素材。
- **原始表格、研究报告、格式转换** → [数据与文档](references/data.md)。先确定数据口径和论证，再处理呈现。
- **想借某个人的思考方式看问题** → [人物视角](references/people.md)。选与问题相关的视角，回到现实证据作判断。
- **造 skill、改 skill、诊断提示词** → [工具与方法](references/tools.md)。分别处理方法提炼、效果验证和指令冲突。
- **CAD、Mac 操作、性能、阅读及其它工具任务** → [工具与方法](references/tools.md)。依赖的应用和运行环境按分支检查。

## 到成员流程的交接

表中的名称是目录里的安装标识。实际 `SKILL.md` 名称不同的，别名写在对应分支旁。按宿主给出的路径或安装目录找到成员，只读取当前分支需要的文件；链接相对该成员目录解析。

用户点名本入口并要求执行时，可以按需读取已安装成员的 `SKILL.md` 作为这项任务的流程资料。这不需要打开成员的自动匹配，也不等同于宿主自动调用了一个被禁用的 skill。交接带上目标、素材位置、已有决定、当前产物和下一步完成条件。

成员缺失或宿主不匹配时，按[发现与安装](references/discovery.md)定位准确来源，并明确缺口。安装文件、运行环境就绪和实际完成作品是三件不同的事。
