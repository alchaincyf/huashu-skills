# 视觉制作

先按交付物选择主流程，再检查宿主、素材与编辑要求。

## 设计与静态物料

| 安装标识 | 何时用 |
|---|---|
| `huashu-design` | 独立仓库的完整 HTML 设计系统：原型、信息图、deck、设计评审。生产 Web 应用的业务与后端由开发流程负责。 |
| `huashu-design-philosophy` | 总目录内的轻量设计哲学顾问：只需比较设计方向或生成设计提示词。其源目录和原始 frontmatter 都叫 `huashu-design`，与完整版并装时将目录和 name 一起改为此别名。 |
| `huashu-slide-codex` | 在 Codex 中用内置生图能力做整页图片 slides、封面和配图。先确认整页图片还是可编辑内容。 |
| `huashu-slide-doubao` | 同类视觉物料的豆包专用流程；使用该宿主的工具契约。 |
| `huashu-slides` | 通用内容到 PPTX 的完整演示文稿流程；按实际素材和环境检查其依赖。 |
| `huashu-gpt-image` | 写或改生图提示词的方法参考：真实视觉锚点、构图关系与失败诊断。实际生成使用当前获准工具。 |
| `huashu-icon-set` | 为项目建立统一图标集；当前实现依赖豆包的图像工具。 |
| `huashu-wechat-image` | 公众号封面、正文插图和信息图的完整制作流程。 |
| `huashu-xhs-image` | 小红书成组配图，关注手机阅读、中文与整组一致性。 |
| `huashu-image-upload` | 已明确需要的配图来源、图床上传和 Markdown 插入；先核实服务配置与上传范围。 |

同一个 deck 选一个主生产流程。只有设计方向不清楚时才补设计判断；只有提示词是瓶颈时才补生图方法。宿主不可用时说明差异，让用户决定替代路线。图片、可编辑页面和真实图表各有交付要求。

## 动画与视频

| 安装标识 | 何时用 / 与相邻路线的边界 |
|---|---|
| `huashu-motion` | 产品发布、更新说明、可编辑动效或解说片，强调节奏、声音和逐帧批注。入口在仓库的 `skills/huashu-motion/`；CLI 和运行文件在仓库其它目录，安装时保留。 |
| `huashu-art-motion` | 艺术风格动画、参考片机制拆解、白板/图表/推导等解说语法。风格卡的研究状态按其索引判断。 |
| `seedance-skill` | Seedance 提示词、白模参考与镜头控制。实际 frontmatter 名为 `huashu-seedance`；模型生成与代码渲染分别验证。 |
| `huashu-design` 的 motion 模块 | 以现有 HTML 设计为中心的小动画、界面演示或延伸产出；先沿已有工程继续。 |

“做个视频”还不足以选路线。先看主体是产品、概念、艺术表现还是生成镜头，是否已有工程与口播，再决定。每支片只用一个主制作工程；跨流程交接传递素材、时间轴和已选视觉方向。

视频选题、脚本口语化与封标检查见[内容与研究](content.md)；口播来源沿用用户已有选择。
